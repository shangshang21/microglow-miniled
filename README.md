# 400 块的便携 Mini LED，找回了黑夜

**简体中文** · [English](README.en.md)

一块京东方拆机面板，一张多接口驱动板，和一次不太肯认命的自救。

花 600 买了台二手便携 Mini LED，退了 200，最后到手 400。很亮，但黑底灰紫灰紫的，像背光全开的普通液晶。卖家说分区背光默认开着，我看到的完全不是那回事。

差点就当普通 IPS 用了。后来不甘心：面板明明有这个能力，到底卡在哪了？

拆机，确认面板和驱动板，和 AI 助手一起从电脑端一路查到固件、面板接口和背光初始化。最后在自己这套硬件上，找到了让分区背光真正工作的路。

所谓神秘的东方力量，大概就是四百块钱买回来了，还不肯认命。

## 现在什么状态

**分区背光日常使用有效。电脑端 OSD 的开关按钮没有产生可见变化。**

两件事都是真的。按钮按下去，控制位读回确实变了，但黑底和光晕没跟着动。是不是得断电才能生效？不知道，也没继续验证。现在满意于分区一直工作的状态，不再折腾开关，也不会把它写成已完成的功能。

公开版停用了分区切换入口，保留亮度、声音、场景、状态读取和动态图案。

## 我怎么找到这条路的

整个过程大致经历了四步：

1. **先确认东西是什么。** EDID 中的名字不等于面板或主芯片型号，拆机标签、板号和实际芯片读取要互相核对。
2. **把图像输出和背光控制分开查。** 面板能正常显示，不代表分区控制已初始化；我这台的下游面板能响应一条专有控制路径。
3. **找到初始化条件。** 在这套硬件上，将 Source OUI 写为 `00 AA 01`，等待后设置面板 DPCD `0x344` 的 bit3，可以进入我确认有分区效果的状态。
4. **把这一步放进启动流程。** 我在核实过的原固件上加入一个 72 字节的自编初始化片段，并修改调用入口；实际不同的字节总数也是 72。自用刷入前后都保留了备份并整片读回核对。

写 Intel OUI 只是打开了面板的这条控制路径，驱动板并没有变成 Intel 产品。

更细的地址、补丁范围和兼容性检查见 [技术说明](docs/技术说明.md)。

## 微光 OSD

拆机时我还弄坏了机身拨轮，所以顺手做了一个 Windows 控制面板。

- 屏幕亮度、对比度、RGB 增益，以及设备支持时的色彩预设、锐度和屏幕音量。
- Windows 默认播放设备的音量与静音。
- 标准、办公、夜读、FPS、电影和个人配方；按实际四项参数识别当前配方，支持恢复切换前参数。
- 晨、午、夜三套主题，可随时间切换或手动固定。主题不会自动调整屏幕亮度。
- 移动白块、交替棋盘和移动细条；Space 暂停、点击定位、Tab 切图案、Esc 返回。
- 托盘、全局快捷键，以及显示器句柄失效后的重新获取。

软件场景是参数配方，不是原厂 FPS 算法。FreeSync 和 HDR 只显示读到的状态，没有假开关。界面目前是简体中文，文档可切换中英文。

**分区开关没有可见作用，公开版不发送 E8 写入。** 没装研究用桥接扩展时，分区状态可能读不到，但不影响初始化补丁和分区效果本身。

## 怎么用这个仓库

仓库里是可构建的源码和一个**只处理本地文件**的启动补丁生成器。没有原厂固件、商业数据库、厂商 DLL 或私有研究仓库的历史。

### 编译微光

直接用可以到 [版本下载](https://github.com/shangshang21/microglow-miniled/releases/latest) 拿 Windows x64 压缩包，解压运行 `MicroGlow.exe`。

从源码编译需要 Windows x64、.NET Framework 4.8 和系统 C# 编译器：

```powershell
powershell -NoProfile -File .\apps\MicroGlow\build.ps1
```

输出在 `build/MicroGlow`。将生成的 `MicroGlow.exe`、`MainWindow.xaml` 和 `MicroGlow.ico` 放在一起运行。可复制 `apps/MicroGlow/install.ps1` 到该目录安装到当前用户，并创建桌面入口。若已有微光在运行，先退出旧版本。

目前只匹配 `RTK2775` 这一台显示器，不是通用 OSD。启动时不会刷固件。

### 从自己的备份生成补丁文件

需要 Python 3.10 或以上，无第三方 Python 依赖：

```powershell
py .\tools\build_startup_patch.py --input "我的原始备份.bin" --output "本地生成的启动补丁.bin"
```

生成器只接受核实过的固件代码版本，保留 bank C 配置，拒绝不匹配或重复打补丁。不同机器的配置可以不同，**但配置区以外的字节必须匹配白名单**。它只生成文件，不读设备、不刷写。

底层刷写流程没有包装成一键工具，请先读 [技术说明](docs/技术说明.md)。不要把原厂固件或整片备份上传到 Issue。

## 这个案例有什么用

最有意思的发现是：不一定要换昂贵的专用板才能有分区效果。至少在我这套组合上，一张保留多接口和音频的普通驱动板，补上初始化之后就能用了。

这给 DIY 多了一个方向。它不需要”所有屏都能用”才有价值。

没测过峰值亮度、分区数量或色准，开关实验也到此为止。
