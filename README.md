# 微光：给 400 元便携 Mini LED 找回黑夜

**简体中文** · [English](README.en.md)

一块京东方拆机面板，一张多接口驱动板，和一次不太肯认命的自救。

我花 600 元买了一台二手便携 Mini LED，后来退了 200 元，最后留下它的成本是 400 元。它很亮，但黑底总是灰灰紫紫的，看起来更像一块背光全开的普通液晶屏。卖家说分区背光默认开启，我实际看到的效果却对不上。

我一度打算就当普通 IPS 用了。后来还是不甘心：如果面板本来就有这个能力，究竟是什么让它没有发挥出来？

于是我拆了机，确认面板和驱动板，和 AI 助手一起从电脑端查询一路查到驱动板固件、下游面板接口和背光初始化。最后，我在自己的这套硬件上，找到了让分区背光真正工作的一条路径。

所谓神秘的东方力量，大概就是四百块钱买回来了，还不肯认命。

## 我现在认可的结果

**分区背光已经能在我的日常使用中工作。电脑端 OSD 的分区开关，仍然没有产生可见作用。**

这是两个不同的结果，我都写在这里。开关请求和控制位可以读回变化，黑底与光晕却没有随按钮明显变化。我不知道是否需要断电等额外步骤才能生效，也没有验证这个猜测。我现在满意于它保持分区背光工作的状态，不再继续折腾开关，更不会把它写成已经完成的功能。

公开版停用了日常分区切换入口，保留亮度、声音、软件场景、控制状态读取和动态图案。开关部分就到这里收尾，先把能用的体验留下来。

## 我怎么找到这条路的

整个过程大致经历了四步：

1. **先确认东西是什么。** EDID 中的名字不等于面板或主芯片型号，拆机标签、板号和实际芯片读取要互相核对。
2. **把图像输出和背光控制分开查。** 面板能正常显示，不代表分区控制已初始化；我这台的下游面板能响应一条专有控制路径。
3. **找到初始化条件。** 在这套硬件上，将 Source OUI 写为 `00 AA 01`，等待后设置面板 DPCD `0x344` 的 bit3，可以进入我确认有分区效果的状态。
4. **把这一步放进启动流程。** 我在核实过的原固件上加入一个 72 字节的自编初始化片段，并修改调用入口；实际不同的字节总数也是 72。自用刷入前后都保留了备份并整片读回核对。

这里的 OUI 数值是这条兼容控制路径的一部分，不代表我的驱动板变成了 Intel 产品。也不要把早期口述与异步日志的到达时间，当成严格同步的光学开关测量。

更细的地址、补丁范围、兼容性检查和取舍，放在 [技术说明](docs/技术说明.md)。

## 微光 OSD

拆机时我还弄坏了机身拨轮，所以顺手做了一个 Windows 控制面板。

- 屏幕亮度、对比度、RGB 增益，以及设备支持时的色彩预设、锐度和屏幕音量。
- Windows 默认播放设备的音量与静音。
- 标准、办公、夜读、FPS、电影和个人配方；按实际四项参数识别当前配方，支持恢复切换前参数。
- 晨、午、夜三套主题，可随时间切换或手动固定。主题不会自动调整屏幕亮度。
- 移动白块、交替棋盘和移动细条；Space 暂停、点击定位、Tab 切图案、Esc 返回。
- 托盘、全局快捷键，以及显示器句柄失效后的重新获取。

软件场景是参数配方，不能冒充原厂 FPS 算法。FreeSync 和 HDR 只有读到的状态与系统入口，没有假开关。当前桌面界面为简体中文；项目文档可在中英文之间切换。

**分区开关没有可见作用，这是已知限制，公开版不发送 E8 分区切换写入。** 状态桥读回也不能证明光学开关。没有安装研究用桥接扩展时，分区控制状态可能不可读，这不等于初始化补丁或分区效果失效。

## 怎么用这个仓库

我公开的是可读、可构建的代码，以及一个**只处理本地文件**的启动补丁生成器。这里没有原厂完整固件、修改后的完整固件、商业数据库、厂商 DLL 或私有研究仓库的历史。

### 编译微光

想直接使用，可以到 [版本下载](https://github.com/shangshang21/microglow-miniled/releases/latest) 获取 Windows x64 压缩包。解压后运行 `MicroGlow.exe`；它是桌面控制程序，不是固件安装器。

需要 Windows x64、.NET Framework 4.8 和系统 C# 编译器：

```powershell
powershell -NoProfile -File .\apps\MicroGlow\build.ps1
```

输出在 `build/MicroGlow`。将生成的 `MicroGlow.exe`、`MainWindow.xaml` 和 `MicroGlow.ico` 放在一起运行。可复制 `apps/MicroGlow/install.ps1` 到该目录安装到当前用户，并创建桌面入口。若已有微光在运行，先退出旧版本。

当前代码只自动匹配唯一的 `RTK2775` 显示器，不是面向所有品牌的通用 OSD。程序不会在启动时刷固件或重新写入背光初始化补丁。

### 从自己的备份生成补丁文件

需要 Python 3.10 或以上，无第三方 Python 依赖：

```powershell
py .\tools\build_startup_patch.py --input "我的原始备份.bin" --output "本地生成的启动补丁.bin"
```

生成器只接受核实过的固件代码版本，保留 bank C 的原有配置，拒绝不匹配、重复打补丁及覆盖已有输出。不同机器的配置允许不同，**但配置区以外的全部字节必须匹配白名单**。它只生成文件和本地报告，不读取设备、不刷写、不分发固件；代码匹配也不能代替具体硬件和面板确认。

我没有把自用的底层刷写流程包装成面向所有人的一键工具。请先读 [技术说明](docs/技术说明.md)。不要把原厂固件或带设备信息的整片备份上传到 Issue。

## 这个案例的价值

对我来说，最有意思的发现是：这套面板并不是只能由某种昂贵的专用板才有机会发挥分区效果。至少在我的组合上，一张保留多种接口和音频功能的驱动板，在补上初始化之后，也有了我想要的表现。

这给 DIY 多提供了一个值得研究的选项。它的价值不需要靠“所有屏都能用”“一键全修好”来证明。

我的边界也很明确：没有测量过峰值亮度、准确分区数量或色准；没有继续验证断电是否影响开关；没有把日常按钮的失败改写成成功。当前实验到这里告一段落。
